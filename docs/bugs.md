# Підтверджені розбіжності з вимогами

Середовище: https://test-me.vzl.one, 21.10.2026, Cypress 15.5.0,
Electron 138, Windows. Токени у доказах не публікуються.
Усі сценарії запису використовують власні ізольовані середовища.
Лог повторного прогону: `evidence/cypress-final.txt`.

## BUG-001 — Пошук не ігнорує крайні пробіли (P1)

Кейс API-002. Передумова: опублікований каталог доступний.
Кроки: GET `/api/products?q=Бездр&limit=20`; потім q=`  БЕЗДР  `.
Очікувано: однаковий непорожній набір p01/p09.
Фактично: другий запит повернув порожній список.
Вплив: скопійована назва з пробілами не знаходить товари.
Перевірка змінює регістр та пробіли разом; для визначення конкретної причини
потрібно окремо перевірити case-only і spaces-only. Тест доводить порушення комбінованої вимоги.

## BUG-002 — Нормалізований WELCOME10 відхиляється (P0)

Кейси M-002-standard, M-002-express. Передумова: новий workspace.
Кроки: POST `/api/quote` із items=[{product_id:p01,quantity:1}], coupon=`  welcome10  `,
delivery=standard; повторити в незалежному середовищі з express.
Очікувано: 200; discount=24000; total=216000/231000 копійок.
Фактично: 422 для обох способів доставки. Контрольний WELCOME10 без пробілів працює.
Вплив: покупець втрачає можливість застосувати валідний код.

## BUG-003 — Стандартна доставка не безкоштовна на межі 1500 грн (P0)

Кейс M-003. Кроки: quote для p02×1, coupon=WELCOME10, standard.
Очікувано: subtotal=150000, discount=15000, shipping=0, total=135000.
Фактично: shipping=8000 замість 0. Тест зупиняється на першій неправильній сумі;
не робимо висновку щодо інших неперевірених граничних значень.
Вплив: нараховується зайва доставка 80 грн.

## BUG-004 — Повторне скасування успішне (P1)

Кейс M-008. Кроки: створити власне confirmed order; POST cancel; повторити POST cancel.
Очікувано: перше скасування 200, повторне 409.
Фактично: повторне скасування 200. Ізоляція доступу чужим токеном у цьому ж тесті пройшла.

## BUG-005 — p07 додається двома рядками (P1)

Кейс UI-004. Кроки: відкрити каталог; знайти Фокус; двічі До кошика; відкрити кошик.
Очікувано: один рядок p07 із quantity=2.
Фактично: два рядки; Cypress `data-cart-line` знаходить 2 замість 1.
Доказ: `evidence/p07-duplicate-cart.png` (знімок діалогу без Command Log).

## BUG-006 — Промокод губиться після reload (P1)

Кейс UI-005. Кроки: додати p01; застосувати WELCOME10; переконатись у відповіді quote;
reload; знову відкрити кошик.
Очікувано: промокод збережено, discount=24000 копійок.
Фактично: discount=0 після reload; застосований код не відновлено.
Доказ: `evidence/coupon-after-reload.png` та Cypress assertion.

## BUG-007 — Контактні поля не застосовують trim перед перевіркою меж (P0)

Кейс M-007. POST `/api/orders` із кожним полем окремо, `payment=declined` для валідних значень.
Очікувано: після trim `name` довжиною 2..80 та `address` 5..200 проходять валідацію
(відповідь 402 через declined payment); невалідні довжини та email повертають 422.
Фактично: `name=" A "` прийняте (402), `name` із 80 символами після trim відхилене
(422), як і `address` із 200 символами після trim (422). Контрольні `name` довжиною 81,
`address` довжиною 4/201 та невалідний email повернули 422.
Вплив: допускається ім'я коротше від вимоги, а валідні граничні значення і крайні пробіли
не обробляються відповідно до контракту.

Очікування не послаблювалися під реалізацію. Останній rate-limited прогін мав 7 Cypress skips
через перерваний `beforeEach` після HTTP 429; ці кейси позначені неперевіреними, не Passed.
