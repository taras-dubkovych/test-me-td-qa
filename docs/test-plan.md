# План тестування

## Мета та оракул

Перевірити вимоги PDF на опублікованому магазині. Очікувану поведінку беремо з вимог,
структуру HTTP повідомлень — з OpenAPI. Фактичну помилкову поведінку не закріплюємо як очікувану.
Ціни API — цілі копійки, UI — гривні. Для quote суми обчислюються незалежно:
subtotal = Σ(price × quantity); discount = floor(subtotal / 10) для WELCOME10;
standard = subtotal >= 150000 ? 0 : 8000; express = 15000;
total = subtotal - discount + shipping. Невідомий промокод → 422.

## Пріоритети

- P0: гроші, stock/quantity, успішна/відхилена оплата, ізоляція замовлень, подвійний клік.
- P1: комбіновані фільтри, обране, review, скасування, повторне замовлення, reset.
- P2: порівняння, мобільний UI, клавіатура, тема, мережеві та порожні стани.

Автоматизовано каталог, частину фінансових правил, checkout, stock, обране, review, ізоляцію та базові UI сценарії.
Наявність коду не означає виконання або підтверджене покриття.

## Дані та незалежність

Для кожного незалежного сценарію запису — новий token. Кожен worker має власний token.
Чужі середовища не використовувати. Контакти: Олександр Тестовий, test@example.test,
Київ, вул. Тестова, 12. Немає справжніх платежів або листів.
Токен живе 24 години; expired-token перевіряти окремим заздалегідь витриманим середовищем,
не симулювати expiry лише клієнтським годинником. Stock не зменшується глобально.

## Ризики та обмеження

Залишковий ризик — неповна гранична матриця, reorder, reset, мережеві стани та доступність.
Каталог у тестах є джерелом даних для перевірки фільтрів, а не оракулом коректності самих цін.
Прямі бізнес-суми слід звіряти з вимогою p01 = 240000 копійок.
Поля/оболонки та UI локатори звірені зі схемою і публічним клієнтом; розбіжності не виправляти під дефектну поведінку.
Перевірка responsive overflow не є аудитом доступності. Flaky-аналіз потребує серії реальних запусків.
Для rate limit не створювати навмисного навантаження; не повторювати POST замовлення автоматично.

## Критерії завершення

Схема та локатори підтверджені; P0 автоматизовані та виконані; кожен fail класифікований
як дефект продукту/тесту/середовища з доказами; відсутні приховані skips; документація узгоджена;
токени не потрапили у Git; опубліковано репозиторій. Наразі ці критерії НЕ виконані.
