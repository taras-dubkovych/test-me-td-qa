# Test Me: Cypress UI та API

Результат підготовки тестового завдання, 21.10.2026. Стек: JavaScript + Cypress.
Тести звертаються виключно до https://test-me.vzl.one; локальний магазин не запускається.

## Статус

Сайт, OpenAPI та публічні HTML/JavaScript отримані. Початкова DNS-помилка була
обмеженням sandbox; дозволений мережевий запит спрацював. Не класифікуємо її як дефект магазину.
Схема тіл запитів підтверджена; оригінальний OpenAPI збережено у `docs/openapi.json`.
Базовий повний прогін 21.10.2026: **41 тест, 34 Passed, 7 Failed, 0 skipped**.
Останній завершений повний прогін 22.10.2026: **44 тести, 36 Passed, 8 Failed, 0 skipped**.
Після розділення M-003 спроба прогону 46 тестів отримала rate limit 429: 32 Passed,
7 Failed, 7 Skipped; це не завершений повний результат. Сім продуктових дефектів лишаються
відтворюваними; BUG-002 має два тести. Деталі — у `docs/execution-report.md`.
Фактичні результати та обмеження див. `docs/execution-report.md`, дефекти — `docs/bugs.md`.

## Запуск

Перевірено на Node.js 20.17.0, npm та Electron 138 із Cypress 15.5.0. Потрібен доступ до опублікованого сайту.

```sh
npm ci
cp .env.example .env   # Windows: Copy-Item .env.example .env
npm run check
npm test
# Або окремо:
npm run test:api
npm run test:ui
```

Версію Cypress зафіксовано; залежності відтворюються через package-lock.json.
Усі spec можна запускати окремо. API workspace-тест створює два власні токени;
UI-тести покладаються на нове ізольоване сховище Cypress перед кожним тестом.
За замовчуванням запускайте послідовно: є обмеження створення середовищ 30/хв.
Паралельні workers не перевірялися; обмеження спільне для клієнтської адреси.
429 слід зафіксувати й повторити запуск після Retry-After; автоматичного повтору записів немає.

## Структура

- `.env` / `.env.example`: конфігурація середовища (BASE_URL, таймаути, viewport, мобільний viewport, невалідний токен). `.env` у git не потрапляє; без нього конфіг читає `.env.example`. Змінні оболонки мають пріоритет. Перевірка дозволеного origin лишається в `cypress.config.js`.
- `cypress/e2e/business.cy.js`: гроші, checkout, stock, обране, відгуки та ізоляція.
- `cypress/e2e/api.cy.js`: каталог, фільтри, сортування, валідація, відсутня/невірна авторизація, нові середовища.
- `cypress/e2e/ui.cy.js`: базовий UI, checkout, подвійне натискання, локальне збереження та мобільна ширина.
- `cypress/support/pages/catalog.page.js`: Page Object для локаторів та основних дій каталогу/checkout.
- `cypress/support/api-client.js`: API client для HTTP-запитів, токенів workspace та безпечних Cypress log defaults.
- `cypress/fixtures/`: статичні дані (клієнти, замовлення/quote-кейси, каталог-кейси та негативні значення) у JSON.
- `cypress/support/factories/`: фабрики payload (`customer`, `order`, `review`) з fixtures та `overrides`.
- `cypress/support/api/`: API helpers (`workspace`, `orders`, `products`) — як створювати/читати дані; тести не будують запити самі.
- `cypress/support/verifications/`: сервіси перевірок. Тести викликають лише їхні методи; `base.verification.js` — внутрішній шар asserts.
  - `catalog.page.verification.js`: перевірки сторінки каталогу/кошика/порівняння.
  - `products.api.verification.js`, `workspace.api.verification.js`, `orders.api.verification.js`: перевірки API каталогу, workspace (авторизація, обране, відгуки) та quote/orders.
- `cypress/support/catalog.js`: перевірений адаптер відповіді каталогу та збір усіх сторінок.
- `docs/test-plan.md`: пріоритети, ризики, межі.
- `docs/test-cases.md`: повні сценарії, включно з тими, які ще треба автоматизувати.
- `docs/execution-report.md`: фактичні перевірки та блокери.

## Межі покриття

API і UI тести містять перевірки очікуваної поведінки, навіть коли продукт їй суперечить.
Не всі ручні кейси автоматизовано: повна матриця review, reset у двох браузерах,
reorder, expiry 24 год, мережеві стани, клавіатура й тема залишаються окремою роботою.
UI-002 перевіряє persistence локального стану; правильні позиції/суми додатково покривають checkout і cart тести.
UI локатори підтверджені публічним DOM. OpenAPI не задає схеми відповідей, тому вони звірені
з реальними відповідями каталогу, quote та orders, а не виведені з `{}` у схемі.
Не слід застосовувати `servers: /qa-lab` із OpenAPI: явна вимога завдання — корінь цього домену.

Автоматичні скриншоти вимкнені: вони можуть містити номер замовлення або токен із діагностики.
Для дефектів робіть окремі скриншоти UI, перевіряючи відсутність токенів. Не публікуйте Command Log,
сховище браузера або тіла відповідей створення workspace. Cypress request із токеном має `log:false`.
Не використовуйте ці токени як параметри командного рядка або CI secrets у відкритих логах.

GitHub-публікація не виконана: наявна локальна авторизація GitHub CLI недійсна.
Архів є локальним результатом, а не заміною URL репозиторію, якого вимагає завдання.
